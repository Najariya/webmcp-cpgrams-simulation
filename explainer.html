What is WebMCP?

A new web standard that lets a website hand AI agents a menu of things it can do — instead of forcing the agent to guess its way through buttons and forms.

Same big idea as MCP… but the website itself is the server, the tools live in the page, and you — the human — stay in the loop.

await document.modelContext.registerTool({ name: "search_issues", … })

the webmcp idea

Let the page speak — give it a tool menu.

With WebMCP, the page itself declares its capabilities as structured tools: exact names, exact inputs, exact outputs. The agent stops guessing and starts calling.

await document.modelContext.registerTool({
 name: "create_report_draft",
 description: "Draft a civic complaint…",
 inputSchema: { … },
 execute: async (input) => { … }
})

One JavaScript call. The browser makes these tools discoverable to any agent — ChatGPT's browser, Chrome's agent, any WebMCP-capable client.

🔧 search_issues
Find complaints by location, category or status.
{ category: "pothole", near: [lat, lng] }
📝 create_report_draft
Prepare a structured complaint for human review.
{ title, description, location, severity }
✅ submit_report
File the approved draft. Requires human confirmation.
{ draftId }

the safety net

The agent prepares.
You decide.

WebMCP is designed for human-in-the-loop work: the agent drafts on the shared screen, and sensitive actions wait for your click.

🏠 Runs in your browser

Tools share your session and your screen — no backend server, no passwords copied elsewhere. readOnlyHint marks safe tools; risky ones can demand confirmation.

👁️ Everything is visible

When a tool runs, you watch the page change — nothing happens in a dark terminal far away.

how it differs from "normal" mcp

MCP over a wire vs. MCP in the page.

🔌 Classic MCP server

a separate backend you build, host & secure
  • Needs its own server, auth and API keys
  • Duplicates app logic outside the browser
  • Your data leaves to another machine
  • Invisible to the user while it works

🌐 WebMCP

tools live inside the webpage itself
  • Zero backend — a static site can be agent-native
  • Reuses the page's live state and UI
  • Runs in your browser session — private by default
  • Every action is visible on the shared screen
Same protocol idea — but the website is the server.
